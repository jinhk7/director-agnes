# 本地短片完整流程 v1

适用：使用 director 在 Infinite Canvas + Agnes 路线上规划、制作、恢复、审片和剪辑短片。用户说“先跑通流程”时交付可播放的流程验证版；不能把剩余质量问题登记为通过。此流程在《北极熊的秘密》中完成了生成、本地备份、剪辑导出和画布播放；音色稳定性、口型与全部镜头质量未全部验收。

## 调用与确认

- “使用 director，把这个故事制作到成片”：从简报开始，按下表分阶段确认，确认后自动推进到导出。
- “继续这个画布/项目”：先恢复状态，不重建已有成功素材。
- “先跑通流程”：优先用已有可用素材剪一版，明确未达标项；不自动消耗无限重做额度。
- “审片并精修”：逐项定位缺陷，在已批准预算内新建修订版本；修改剧情机制或超出预算才询问。

用户已确认的默认方式为“分阶段确认后自动制作到成片”。需要确认的是创意与视觉声音选择、必要且未授权的费用范围、改变故事的取舍；常规连线、验收、同范围生成、局部修剪、备份和导出不再逐次询问。已有授权能涵盖下一步时继续。渠道/价格信息缺失先检查当前状态，不能仅因旧文件写了“每次确认”就重复询问。

## 阶段与交付

|阶段|完成的工作与记录|推进条件|
|---|---|---|
|0 恢复与简报|读取当前画布、项目文件、用户最近指令；明确故事、画幅、时长目标、平台、质量目标、字幕/旁白/音乐选择与预算范围|确认目标；导入项目时映射新旧画布ID，核验实际素材|
|1 创意与风格|选Mode，保留原故事因果和结局；必要时提供少量画风样张|用户确认故事改编与风格；不重新确认已选择项|
|2 参考资产|人物身份/多视图、关键场景、道具、外观状态卡；角色声音试听，视频声音提取为独立音频|用户确认人物、关键参考与音色；无对白角色不强制建声音|
|3 分镜细化|每镜写 start_state/action/end_state/camera/dialogue/引用职责；确定镜间连续性与剪辑职责|剧情、对白不变时自主细化；新增改变因果的动作先确认|
|4 动作首帧|从母图编辑每镜独立静态首帧；实际放大看图；审查身份、姿态、道具、污迹、场景和动作空间|首帧验收通过，且起点不等于终点；不通过先改图|
|5 连线与提交|核对实际图片、storageKey、模式、引用数量/顺序、展开提示词和模型参数；保存版本并提交|已获生成范围授权；先用代表镜检验通道，再按项目并发补位|
|6 任务与审片|记录任务ID、轮询结果，保存本地媒体；检查动作、道具、背景、连续性、对白与口型|文件完整与创作验收分开；失败只修所需镜头，不整批重做|
|7 剪辑|按内容选入出点，保留关键因果和完整台词；统一画幅/帧率/采样率，处理接缝，按已确认设计加入文字或音乐|保存可复现剪辑清单；裁剪与省略不得无声删去关键叙事|
|8 交付|导出独立本地MP4，解码检查，实际播放器首中尾及切点检查，画布成片节点；记录问题和版本|交付可播放成片及准确验证范围，不仅交节点/URL|

## 首帧与连续性门槛

画布中的英文提示词旁必须放置同镜头、同用途、同版本的完整中文审核文本框；中英文同步修订，中文框不接入生成配置。布局和引用规则见 [工具适配](../tools/infinite-canvas-agnes.md#中英文提示词审核布局)。

母图锁身份和环境，动作首帧锁零时刻。首帧只写可见静态事实：画面左右、头/鼻尖/视线、嘴和爪子状态、与物件的间隙及站位。不要用“即将/准备”代替姿态，也不要在一张图里叙述完整动作。

视频描述从实际首帧到终态的可见过程与停留；若实际图已转头、已戴镜或已抓住道具，不能靠视频指令偷偷复位。实际图与计划起点不同但仍能表达动作时，可修订视频动作，另存新版本并说明。

连续性矩阵至少覆盖角色数、身份、服装/污迹状态、道具数量和方向、场景元素、屏幕运动方向。第一次审核不能只看主角头部。视频中无来源的棚架、芦苇、多余角色、污迹消失均记录为缺陷。倒影必须是同一主体的物理反射，不能接受水下站立的第二只动物。

对白使用准确原句和唯一可见说话者，音频参考只锁声音身份，不把试听句复制为台词。参考声音提取后核验时长/采样率/声道及可播放性，保留源视频与新WAV。静音检测只能辅助选择切点，不能证明说对了台词；嘴在动也不证明口型同步。

## 状态与恢复

复制 [项目模板](../assets/local-film-project.template.json) 到作品目录作为 `production.json`，填入真实信息。JSON是当前状态入口，Markdown由它和验收证据整理，不维护两份互相冲突的“当前状态”。历史提示词、生成记录、旧素材只增版本，不覆盖。凭证不进入模板或作品记录。

阶段建议：`brief → references → storyboard → keyframes → generation → review → edit → delivered`，可按缺陷退回指定镜头。任务状态单独用 `not_submitted/submitted/running/succeeded/failed/unknown`；素材验收单独记录 `pending/pass/fail/not_applicable`、证据来源及时间。

“继续”时读取 live canvas 和 production.json，逐镜对账：成功结果有文件则复用；已有task_id先续查；未知是否提交时不重复发送；超时不代表供应商失败。运行与未知未终结任务都占并发名额。已知失败且允许重做，创建新attempt并关联旧任务。无法查询或授权不足时暂停相关镜头，其余独立工作继续。

## 本地作品包

每部作品单独目录：`production.json`、`prompts/`、`images/`、`audio/`、`video/`、`reviews/`、`edits/v001/`、`exports/`。不强制搬迁历史文件，恢复时登记原路径即可。

- 每个成功资产应有本地文件、字节数或哈希、节点/素材ID和来源记录。浏览器blob不是备份；不要把容器临时副本当唯一媒体源。
- 换浏览器通过画布正式打包导出/导入迁移，并核验节点、连线、图片、声音、视频和渠道配置；同一个localhost网址不代表共享浏览器数据。
- 成片回画布后保留本地权威文件。若用本地服务URL，应说明服务依赖；临时容器副本重建后可能丢失。用正式上传/存储功能优先于临时副本。
- 公共skill仓库只放通用规范、模板、脚本与脱敏经验；作品、人物、声音、任务ID、私有渠道配置留在作品目录。

## 审片与剪辑的完成定义

分别记录：生成成功、文件可读、实际播放、动作、视觉连续性、对白、口型、叙事完整性。证据来源分 `assistant_visual/assistant_listening/user_report/tool_check`。未听过不得标记对白通过；用户对旧片的反馈不能复制到新片。

剪辑前先看代表帧和关键动作，出现异常再加密检查；对白段要试听，确认首尾不截字。剪掉镜头或裁掉画面前说明其叙事作用如何保留。若剪掉倒影就失去“发现秘密”的证据，应登记为叙事缺口，不能称完整保留揭晓。流程验证版可以交付此类已披露缺口；正式质量版需修补或用户接受取舍。

通用本地剪辑能力见 [剪辑清单模板](../assets/local-film-edit.template.json) 和 [render_edit.py](../scripts/render_edit.py)。用实查的FFmpeg路径调用：

```text
python scripts/render_edit.py path/to/edit.json --ffmpeg path/to/ffmpeg --output path/to/exports/film-v001.mp4
```

脚本只读本地素材，按清单裁切/硬切，统一编码，补齐缺失音轨，支持裁剪和首尾淡化，写实际帧边界清单并做完整解码检查。已有输出不覆盖。无需网络，不上传素材、不生成媒体。它不替代审片，也不提供智能配乐、字幕或口型修复。导出后仍需在用户实际播放器验证，并以本地MP4直接交付。

## 本次流程的保留与纠正

保留：分阶段选择风格和声音、从视频提取音频、逐镜动作首帧、按实图修提示词、并发上限3、原任务恢复、本地备份、30秒剪辑成片、画布播放。

纠正：首帧验收不足以保证生成视频；错误背景和额外角色应在剪辑前发现。S01/S06弃用、S07裁剪是一次流程样片的修剪决定，不是可复用的固定剪辑。首次成片未完成对白听写和口型验收，不能宣称全项质量验证。后续按项目质量目标明确补拍或接受缺陷，不把“跑通”自动升级为“发布级成片”。
